=========================================================================
File headers to use in the Nef repository
=========================================================================

Copy the block that matches the file type. Keep the year and holder identical
across the whole repository: `Copyright 2026 Feng Tao (Nate)`. Do not use
"the Nef Project" or a fake organisation name — for relicensing and
enforcement you want the copyright holder to be a real, identifiable person or
entity, and for a solo project that is you.

<!-- --> for HTML, and the language's own convention elsewhere. The wording
must stay the same; only the comment syntax changes.

-------------------------------------------------------------------------
2. Files covered by the Output Exception (runtime, stdlib, headers)
-------------------------------------------------------------------------

Status (2026-10-28): every `.go` file under `compiler/` now carries block 1;
the runtime sources in `compiler/internal/runtime/` carry this extra paragraph
after it. Test files and fixtures carry the one-line form in block 3.

Add one line after the standard Apache block so that anyone reading the file
sees the exception immediately. This matters: it is the line that stops a
company's legal review from stalling adoption of Nef.

// Copyright 2026 Feng Tao (Nate)
//
// SPDX-License-Identifier: Apache-2.0 WITH Nef-Output-Exception
//
// Licensed under the Apache License, Version 2.0 (the "License");
// you may not use this file except in compliance with the License.
// You may obtain a copy of the License at
//
//     http://www.apache.org/licenses/LICENSE-2.0
//
// The Nef Output Exception (see the LICENSE-EXCEPTION file at the repository
// root) applies to this file: code you write and the binaries you compile with
// it are not subject to the Apache License, and you have no obligation to
// open-source them.

-------------------------------------------------------------------------
3. Test files and trivial files
-------------------------------------------------------------------------

Tests, fixtures and one-line files may carry only:

// Copyright 2026 Feng Tao (Nate). Apache-2.0. See LICENSE.

Keep the full block on anything non-trivial.

-------------------------------------------------------------------------
4. Third-party / vendored code
-------------------------------------------------------------------------

Never overwrite an upstream copyright header. Leave the original header intact,
add your modification notice below it, and add an entry to NOTICE. If an
upstream license is GPL or AGPL, do not vendor it into Nef — it would force the
whole toolchain to become copyleft and would make the Output Exception
unworkable.

-------------------------------------------------------------------------
5. SPDX identifiers to use in manifests
-------------------------------------------------------------------------

  LICENSE / whole toolchain : "Apache-2.0 WITH Nef-Output-Exception"
  source files (.go, .nf)   : "Apache-2.0"
  spec + docs               : "CC-BY-4.0"

"Nef-Output-Exception" is a project-local exception identifier, not an SPDX
listed exception, so tooling may flag it as unknown. That is expected and
harmless; state it in the README so contributors do not "fix" it.

Two files hold the two texts since 2026-10-28: `LICENSE` is the unmodified
Apache-2.0 text, so compliance scanners and the repository host read the
license correctly; the exception lives in `LICENSE-EXCEPTION` and is an
additional grant under Section 4 of that License. In file headers use the plain
"Apache-2.0" identifier, because these sources are the licensed material
itself - the exception speaks about the output you compile, not about them.
