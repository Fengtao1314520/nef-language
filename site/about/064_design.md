# 设计取舍

Nef 在五个地方与常见做法不同：直接生成机器码、不做垃圾回收、类型标注不可省略、包用源文件分发、只输出 Windows x86-64 的产物。

| 定下来的做法 | 为什么 | 要接受的代价 |
| --- | --- | --- |
| 编译成机器码，不经过字节码与虚拟机 | 产物只需要 Windows 自带的系统 DLL，拷走就能运行；没有预热，也没有回收造成的停顿 | 所有检查都要在编译期做完，运行期不能改变这些结论 |
| 不做垃圾回收，一个值只有一个持有者 | 释放的位置写在代码里，测试能一条一条核对 | 写代码要理解“交出”与“只读借用”这两种传递方式 |
| 类型标注不可省略，不做隐式转换 | 读一行就知道那里的值是什么种类、归谁持有 | 同一句话要多写一段类型 |
| 包分发源文件，用的时候当场编译 | 没有中央仓库，包不跟着编译器版本发二进制，换一个工程照样能编 | 每次编译都重编一遍包里的源文件 |
| 只输出 Windows x86-64 | 系统调用面只有一份，行为可核对 | 同一份源码在 Linux 与 macOS 上生不出可执行文件 |

具体规则写在[语法参考总览](/reference/033_index)与[标准库总览](/stdlib/044_index)里，这一页只说理由。

## 编译成机器码

编译器一次读源码，直接写出 x86-64 指令与 PE 可执行文件：没有字节码，没有虚拟机，也不链接 C 运行库。

产物运行时用到的东西只有 Windows 自己带的系统组件。

`nf build` 生成的 exe 拷到另一台 Windows 机器上，那台机器不需要装任何东西。这条性质来自后端的约定：产物只向系统目录里那几个 DLL 要东西（`compiler/internal/pe`、`compiler/internal/runtime`）。

## 一个值只有一个持有者

赋值、`return`、传参都是把持有关系转出去，旧的名字当场失效。

持有者走到作用域尽头时，它持有的那块内存被释放，生成的代码里直接带着释放的那几句。除了垃圾回收，语言也不提供引用计数、生命周期标注和成批回收（arena）。

这个选择最实在的好处是可以核对：一段循环跑两万轮之后堆上还剩多少字节，是一个测试能核对的数字。仓库里那几条两万轮的测试固定着它，各组页面里也写着对应的实测数字。

代价是要读懂两种传递方式。把值交给别人写“交出”，只是借来看一眼写“只读借用”，用错的那一处编译器会报错。

改之前得先明白它为什么报。这条规则在[值的所有权](/learn/026_ownership)与[值与存放](/reference/038_memory)里完整讲过。

## 类型标注不可省略

`let` 与 `const` 要写类型，函数的参数与返回值要写类型，容器要写元素类型。

类型之间不做隐式转换，要换面就写 `as`。

多写的那一段类型换来的是不用回头找定义：`let count:int = 0` 这一行自己就说明它是一个整数。省略标注会被当场拒绝，编译器的原文是 `声明 count 必须标类型`。对照示例在[变量与类型标注](/learn/023_values)。

## 包分发源文件

一个包是一个 `.nfpack` 文件，里面装的是源文件与它自己用到的依赖。安装就是把这份文件放进工程的 `libs/` 目录，编译时不联网。

```json
{
  "name": "greet",
  "version": "1.0",
  "deps": { "shout": "2.0" }
}
```

版本写死，不比较大小、不写范围、不挑版本；工程要的那一版与 `libs/` 里那一份对不上，就是编译错误。

包里的文件看不见工程里的名字，所以同一份包换一个工程还得照样能编译。规矩写在[多个文件](/reference/042_modules)。

## 只输出一种产物

后端只生成 Windows 上的 PE 可执行文件。网络、文件、进程、时间这些功能直接调用系统自带的 kernel32、ws2_32、winhttp，不带额外运行库。

这是后端的实现范围，不是语言的规则：换平台要重开的是可执行格式、调用约定、系统调用面、取块规则、控制台编码这五处约定，语言本身的写法不受影响。

## 编译出来的东西有多大

`samples/` 里四份程序各编译一次，源码与产物的实际字节数如下。

| 程序 | 源文件 | `nf build` 生成的产物 |
| --- | --- | --- |
| `shopping.nf` | 1,180 字节 | 298,496 字节 |
| `stock.nf` | 1,463 字节 | 301,568 字节 |
| `shapes.nf` | 1,731 字节 | 301,568 字节 |
| `rpn.nf` | 2,463 字节 | 303,616 字节 |

四份产物的大小相差不到 5.2 KB，它们自带的运行期是同一份：产物里绝大部分不是这段源码编译出来的代码。

内存占用在程序自己身上。设置 `NEF_HEAP` 之后，产物退出前打印一行 `heap <累计> <链上>`：累计是这一趟向堆申请过的字节总数，含已经归还的；链上是结束时还挂在空闲链表上、等着复用的字节数。两者之差就是仍在使用的那部分。

```text
$env:NEF_HEAP = "1"
./nf.exe samples/shopping.nf
```

```text
共 3 件，字符数合计: 7
算完了
heap 224 184
```

不带参数就能跑完的那四份程序，两个计数的实测值如下，“仍在使用”是两者之差。

| 程序 | 累计 | 链上 | 仍在使用 |
| --- | --- | --- | --- |
| `shopping.nf` | 224 | 184 | 40 |
| `shapes.nf` | 256 | 184 | 72 |
| `rpn.nf` | 720 | 512 | 208 |
| `stock.nf` | 1,032 | 840 | 192 |

`linecount.nf` 与 `wordfreq.nf` 不在这张表里：它们开始时会把命令行上的参数逐条构造成文本，参数写得越长，这两个数越大，换一个参数就是另一组数。上面四行是 2026-10-29 实测的，按上面那两条命令就能重取。

耗时的毫秒数不放在这一页：同一台机器第二天测出来就可能不同，能对照的只有改动前后的同一批测量。

## 语法保持小

三元运算符、解构赋值、多返回值、命名实参、容器之外的泛型、把函数当值传递，这些都没有。

`break` 与 `continue` 只作用于最内层循环，要跨层退出就改用函数返回值。
