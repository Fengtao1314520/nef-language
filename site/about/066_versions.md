# 版本与兼容

编译器用 `v0.MINOR.PATCH` 三段版本号，`nf version` 打印当前这一版。这一页说明三位数各自在什么时候变、`0.x` 阶段承诺什么、升到 `1.0.0` 还差什么。每一版改了什么，记在仓库根的 `CHANGELOG.md`。

版本号只说改动，不说计划。

## 三位数各自什么时候变

| 升哪一位 | 什么时候变 | 已经发生过的一次 |
| --- | --- | --- |
| `PATCH`（`v0.5.5`） | 同一档里攒下的一版：修缺陷，也带这一档里的语言改动，只要没有添一整层能力 | `v0.5.5`（2026-11-05）发的是 `try` 后面的 `finally`、没人接住那一次抛出的调用链、包容器的校验值与两处修复，报错原文从 359 句到 370 句；这些写法都接在既有的 `try`、抛出与包这三样上，没有新添一整层，所以号进在末位 |
| `MINOR`（`v0.5.0`） | 语言添了一整层：能写出一整类以前写不出的程序 | `v0.4.0` 多了 `ref` 这个记号，参数前面写 `ref` 就是只读借用，另外多出七句报错原文；`v0.5.0` 多了函数当值与抛出那一步的位置，`catch` 跟着多一个名字；`v0.7.0` 多了 `http.request` 这一条底层动作，自定义请求头、七种方法、应答上限与证书开关都跟着它进来；`v0.8.0` 把压缩应答补齐（deflate 由库自己解）并让 `http.get`/`http.post` 也能带请求头 |
| 升到 `1.0.0` | 下面三个条件全部达到，缺一条就不算 | — |

## `0.x` 阶段不承诺向后兼容

`v0` 这一档里，`MINOR` 与带语言改动的那一版 `PATCH` 都可能改动语言行为：以前能通过检查的写法可以变成错误，一句报错的说法也可以换掉。

要固定行为，就把编译器的版本号写进自己的构建脚本里，用 `nf version` 对照。

一句报错改了说法，也算语言行为变了一轮。

添的是一整层能力就升 `MINOR`，只是把同一档里攒下的改动发出去就进在 `PATCH`。

每句报错都在仓库里的一张表上逐句比对（`compiler/testdata/报错文字.txt`），改一个字检查就失败。[错误信息索引](/tools/060_errors)收录的就是这批原文。

## 升到 `1.0.0` 的三个条件

1. **语言的规则逐条定下。** 从基础类型、语句、函数到容器与错误处理，每一条规则都已经写定，改动它要先有一条新的决定跟上。和可执行文件格式、后端实现有关的那几条有意不写死：换平台、换可执行文件格式一定要改动它们，写死了反而妨碍跨平台；规则还没补全的那一小部分也照实留着。
2. **每句报错都有表逐句比对。** 前面说的那张表已经做到：改动一句报错原文，检查当场失败。
3. **至少有一个不是这套工具自己写的程序，在这套工具链上运行。** 这一条要等对外发布之后才会出现。

## 怎么确认手上是哪一版

```text
nf version
```

开发用的构建打印 `nf dev`；带版本号的构建打印 `nf v0.8.0` 这一种。打印出 `nf dev` 只说明这份构建没有注入版本号，不代表编译器有额外的改动。

VS Code 插件与编译器同号发布：插件的 `0.8.0` 对应的就是编译器的 `v0.8.0`，同一轮的语言改动两边一起走。

插件不带编译器，用哪一份由设置里的 `nf.path` 说：填了就用那一条，留空就按 `PATH` 里的 `nf` 找。编辑器里报错的那一份与命令行上运行的因此始终是同一个。用法与安装写在[编辑器与调试](/tools/061_editors)。
