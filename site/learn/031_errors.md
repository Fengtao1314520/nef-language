# 错误处理

从文件中读取一个金额，文件可能不存在，文件里的金额也可能写成“三十”而不是 `30`。函数该返回什么？

返回 `0`，统计结果就错了；返回一个“可能是数字也可能是空”的值，则每次调用之后都要判断一次，漏判一次，空值就会被当成数字继续参与运算。Nef 选择的是第三种做法：**失败用异常传回**。`throw` 抛出，调用方用 `try`、`catch` 捕获。抛出的内容永远是两个值：一个整数错误码，一条消息。

## 异常的格式

```nf
method check_age(n:int):int {
    if (n < 0) {
        throw (100, "年龄不能是负的")
    }
    return n
}

try {
    console.print(check_age(30))
} catch (code, msg) {
    console.print("接住了:", code, msg)
}
```

```text
30
```

把 `check_age(30)` 换成 `check_age(-1)`，执行的就是 `catch` 分支，屏幕上输出 `接住了: 100 年龄不能是负的`。

`throw` 后面必须紧跟一对括号，括号内恰好两个值，顺序是错误码在前、消息在后。少一个值、省略括号、抛出其他类型，都是编译错误。

抛出本身也不返回任何值。`let x:int = throw (100, "a")`、`f(throw (100, "a"))` 这类出现在取值位置的表达式不被接受：`throw` 是语句，没有返回值。

`catch` 只有一种形式：`(code, msg)`，两者一起接收。这两个变量是 `catch` 块内的局部变量，离开这个块就失效。

`catch` 不筛选错误码：任何错误码抛出都会进入同一个块。需要按错误码分别处理时，就在块内自己写 `if` 或 `switch` 判断。

码值分段是硬性规定：`10000` 以上属于语言内置错误，程序自己的错误码写在 `0` 到 `9999`。占用语言那一段是编译错误，编译器的提示是“throw 的码从 0 写到 9999”。

编译器能核对的只有**直接写出的码**，也就是字面量本身。错误码来自变量时无法确定具体的值，`throw (k, "x")` 能通过检查，运行时按变量里的值抛出，例如 5。要让分段规定完全可靠，就应当避免把变量直接作为错误码。

## 函数签名上不标注异常

没有 `throws` 一类的记号。一个函数是否可能抛出，不必声明，编译器也不要求调用方必须捕获。

需要处理就写 `try`，不处理就让异常向外传播。

```nf
method read_age(one:string):int {
    return text.to_int(one)
}

try {
    console.print(read_age("30"))
} catch (code, msg) {
    console.print(code, msg)
}
```

```text
30
```

`read_age` 没有 `throws` 标记，它照样会抛出：其中的 `text.to_int` 解析“三十”时会抛出 10012 号错误。要么在这个函数里写 `try`，要么交给调用方处理，中间的函数不需要跟着修改声明。

带 `throws` 标记的语言里，标记会沿着整张调用图往下传递：调用链末端的一个小函数改成“可能抛出”之后，路径上每个中间函数都要跟着修改声明，而它们本身并不处理这个错误。Nef 没有这个负担：抛出的形式统一，永远是同一个错误码配一条消息，需要在何处接收就在何处写 `try`。

## 语言自己那批码

不需要自己写 `throw` 也会遇到异常：拆箱时类型不匹配、文本无法解析为数字、下标越界、键不存在、遍历过程中修改容器、内存申请失败，以及通过空引用访问成员，这些都由语言在运行期抛出。

这一课只要记住分段：**`10000` 以上属于语言内置错误，程序自己的码写在 `0` 到 `9999`**，占用语言那一段是编译错误。哪种情况对应哪个错误码，完整表格见[出错的时候](/reference/041_errors)。

这些不是无法捕获的崩溃，抛出的形式与手写 `throw` 完全相同：

```nf
let a:list<int> = [1, 2, 3]

try {
    console.print(a[9])
} catch (code, msg) {
    console.print("接住了:", code, msg)
}
```

```text
接住了: 10031 下标越界
```

## 异常传播与资源清理

抛出时当前函数立即结束，该函数作用域内已经创建的值按声明的反序释放；正常执行完毕与抛出采用同一套清理流程。

随后控制流沿调用栈逐帧向外查找，遇到第一个 `catch` 就停下执行它；找不到就退到调用方所在的帧。

沿途经过的每一帧各自清理：逐帧退出，帧内已创建的值按声明的反序释放。

```nf
method one() {
    let a:list<int> = [1, 2, 3]
    let x:int = a[9]              // 在这里抛出：下标越界
    console.print(x)              // 这一行不会执行
}

try {
    one()
} catch (code, msg) {
    console.print("接住了:", msg)
}
```

```text
接住了: 下标越界
```

语言没有 `finally`。

清理不需要手写：作用域结束就自动释放，因此抛出也不会遗漏清理。需要把错误继续向上传递时，把错误码和消息再次 `throw` 传出去，没有单独的重抛语法：

```nf
method read_age(one:string):int {
    try {
        return text.to_int(one)
    } catch (code, msg) {
        if (code != 10012) {
            throw (code, "这一层处理不了")
        }
        return 0
    }
}

console.print(read_age("三十"))   // 0
```

## 未捕获异常

如果最终无人捕获，程序终止，屏幕上只输出一行信息，返回给操作系统的退出码是 `1`：

```text
出错了（10031）：下标越界
```

括号内是错误码，冒号后是消息。

没有文件名、行号、调用链：这些信息要求产物额外携带一张行号对照表，与直接生成机器码这一目标相冲突。

需要定位时就在捕获之后自行打印。常见的做法是在 `catch` 里把函数名一并放进消息。

希望以自己的错误码结束程序时调用 `exit (code, message)`：括号与顺序同 `throw` 一致，区别在于调用方无法捕获它。

## 编译期错误无法捕获

能够被 `catch` 的只有运行期抛出的错误。

类型不匹配、声明缺少类型标注、使用已经交出所有权的名称、函数存在未返回值的路径、`switch` 漏掉枚举成员又没有 `default`，这些都发生在编译期，程序根本不会开始运行。

因此也不存在可以捕获它们的位置。

它们连同文件、行号、列号一起报错。常见的错误以及编译器的原文收录在[错误信息索引](/tools/060_errors)。

## 练习

把 `read_age("30")` 换成 `read_age("三十")`，先写下预期的错误码，再运行验证。

然后在最外层再套一个 `try`，判断内层的 `catch` 是否还会执行。先判断哪一层会接收，再修改代码。

## 本节要点

失败是一条 `(码, 消息)`，语言内置错误采用完全相同的形式，都可以捕获；不做处理就向外传播，最外层仍无人接收时程序终止，退出码为 `1`。
