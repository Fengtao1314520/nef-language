# 值与存放

一个值什么时候归属于某个名称、什么时候不再归属于这个名称、什么时候被释放，由下面几条规则决定。

## 地基

| 项目 | 规则 |
| --- | --- |
| 两类类型 | 值类型定宽、赋值整份拷贝、不可为 `null`；`struct` 是值类型，名称中保存的是 8 字节的句柄，字段数据在堆上，整份拷贝复制的是堆上的整块数据。引用类型指向对象，赋值即交出，旧名称随之失效 |
| 存储与释放 | 局部值随作用域结束自动释放，顺序是声明的反序。堆上的对象有且只有一个持有者：赋值和 `return` 都是交出，交出后旧名称立即失效；持有者所在的作用域结束时释放 |
| 不引入的机制 | 没有垃圾回收，没有引用计数，没有生命周期标注，也没有把一批值放在一起回收的机制 |
| 默认值 | 值类型是零值，引用类型是 `null`。不存在未初始化的内存 |
| 转换 | 只经 `as` 显式转换，没有隐式转换，没有隐式装箱 |

这些都由编译器全程检查，违规是编译错误。

## 什么操作算交出

引用类型在这五个位置会改变持有者：

| 位置 | 写法 | 结果 |
| --- | --- | --- |
| 赋值 | `let b:string = a` | `a` 失效 |
| 传参 | `f(a)` | `a` 失效 |
| 返回 | `return a` | 函数内的名称随函数结束失效，值交给接收它的名称 |
| 容器进出 | `let x:string = box[0]`、`box.add(s)`、`let xs:list<string> = [s]` | 读出的值归新名称，写入的值归容器；`s` 不再是持有者 |
| 装箱 | `box.add(c as object)` | `c` 不再是持有者 |

值类型走的是另一条规则：赋值是整份拷贝，函数体内怎么修改都不影响调用方，也无法把修改写回调用方的变量。

```nf
method shout(t:string) {
    console.print(t)
}

method make_line(word:string):string {
    shout(word)             // word 交出去，这个函数里此后不能再写它
    return "好了"
}

console.print(make_line("喂"))
```

```text
喂
好了
```

这两行输出都由这段代码产生：`shout` 先接收 `word` 并把它打印出来，`make_line` 再返回一句 `"好了"` 交给外层打印。`shout(word)` 执行完的那一刻 `word` 就失效了，此后在这个函数里再写它就是编译错误。

## 借用

两个名称同时指向同一个值的情况只有下面几处。这四条叫只读借用，共同点是**借入的一方拿不到所有权**：

- **遍历交出的值。** `for (c:C in cs)` 的 `c` 是一个只读别名：可以读取字段，可以调用方法，但不能交出所有权：`let d:C = c`、`return c`、`cs2.add(c)` 都是编译错误，拆箱时 `c as T` 同样是编译错误，本轮迭代结束后就失效。遍历结束后容器仍然是完整的。需要把对象真正取出时，按下标写 `cs[0]`，对应位置随之变为空。
- **标准库十四个内建组接收被操作的对象。** `items.add(9)`、`length(items)`、`console.print(txt)`、`s.split(",")` 执行结束后，`items`、`txt`、`s` 的持有者没有变化。
- **标了 `ref` 的参数。** `method total(ref xs:list<string>):int` 里那个 `xs` 只是借来使用：调用方的名称在这次调用之后照旧能用，函数里可以读取、调用方法、就地修改，不能 `return`、写进字段、装进容器、装箱，也不能交给一个没写 `ref` 的参数。值类型的参数不许写 `ref`，`Socket`、`Listener`、`Process` 这三类句柄也不许写。
- **方法接收者，也就是方法体中的 `this`。** 可以读取字段，可以就地修改这个对象，可以连续调用方法（`c.bump()` 执行结束后，`c` 的持有者没有变化）。但不能把它交出：`return this`、`give(this)`、`box.add(this as object)` 都是编译错误。

标准库对被操作对象单独规定为借用的理由是：如果每操作一次就接管所有权，往 `list` 中添加一个元素就得把整个容器交出去，那样容器就无法使用了。

自定义函数**没写 `ref` 的那些参数**不在借用之列，按上表交出；写了 `ref` 的、以及方法左侧的接收者，与标准库遵循同一条规则。

一个对象只能有一个持有者，`this` 如果能交出去就会出现两个持有者。需要返回一个对象时，用 `new` 创建一个。

## 从字段里读出来的值

`class` 的字段装着引用类型时，**读出来就是交出**：与容器中存放元素的位置遵循同一套规则。

`let a:Inner = o.i` 之后，`o.i` 返回 `null`：持有者换成了 `a`，对象中不再保存它。再次写 `let b:Inner = o.i` 时，`b` 得到的是 `null`，用它继续访问成员就是 10092 号错误（`对着空句柄取成员或调用方法`）。

不是每次读取都算交出，分界线是“有没有多出一个新持有者”：

| 读取写法 | 算不算交出 |
| --- | --- |
| `let a:Inner = o.i` | 算：值由一个新名称持有 |
| `feed(o.i)`、`bag.add(o.i)`、`return o.i`、`o.i as object` | 算：作为实参交出、写入容器、返回给调用方、装箱 |
| `console.print(o.i.v)`、`length(o.name)`、`o.list.add(x)`、`o.i.v = 5` | 不算：继续读取成员或者就地修改，没有新持有者 |

需要把值放回字段时直接写回即可：`o.i = a`，`a` 当场失效，`o.i` 重新成为持有者。

值类型字段（`int`、`float`、`boolean`、`byte`、`unicode`、`struct`、`enum`）是整份拷贝，字段值读取多少次都仍然存在。`struct` 自己的字段也不适用这条规则：`struct` 是值类型，读取它的字段得到的是整份拷贝。

因此同一个对象不可能有两个持有者：先放进字段、再读出来，这种做法会造出两个持有者，同样被禁止。需要在两个地方使用同一个对象时，把同一个名称传入两次，或者传出之后写回字段。

## 什么时候释放

一个作用域结束时，该作用域内声明的值按声明的反序释放。函数、块和文件顶层遵循同一套规则。

顶层只有一处不一样：**它的释放点是整个程序执行结束，而不是本文件执行到最后一行**。

理由是：被 `import` 的文件先执行，但它顶层的 `let` 之后还要给本文件的函数使用，而本文件的函数可能在其他文件的顶层中被调用。

因此次序是：各文件的顶层依次执行完，然后从入口文件的最后一个声明开始向前释放，一直释放到最先执行的文件的第一个声明，最后才返回退出码。`export shared` 声明的名称不参与这一过程。

顶层的循环体与 `if` 块中声明的名称不算作顶层声明：它们属于栈帧，每执行一轮、每经过一块就释放，与函数中的规则相同。

```nf
method build():list<string> {
    let parts:list<string> = ["甲", "乙"]
    return parts            // parts 随函数结束失效，容器交给接住它的人
}

let all:list<string> = build()
console.print(length(all))  // 2
```

| 情况 | 表现 |
| --- | --- |
| 函数内 `throw` | 抛出时所在函数的值按声明的反序释放，与正常执行完毕相同；抛出跨过的每一帧也逐帧释放，捕获它的帧中 `try` 体登记的值同样释放。从 `try` 体中间离开（`return`、`break`）时，也先释放应当释放的值，再让这一层的名称失效。语言中没有 `finally` |
| `exit (错误码, 说明)` | 只取消尚未执行的代码：所在函数与顶层的一批值照常释放；抛出逐帧释放的规则在这里不适用 |
| 传给函数的值 | 参数没写 `ref` 时名称当场失效。被调方没有保留它（没有 `return`、没有写入字段、没有装入容器），就在调用方所在的作用域结束时释放；参数前写了 `ref` 的那一处只是借来看，名称不失效，那一块仍然由调用方释放；被调方保留了这个值，就由接收它的持有者负责释放 |
| 一条语句中没有名称接收的值 | 在这一句结束时释放。`xs[0];`、`xs.first();`、`xs.remove_at(0);`、`"甲" + "乙";`、`xs.slice(0, 1);` 单独写成一句时，读走或者新产生的值没有名称接收，当场析构；`d.remove("k")` 删掉的那条记录，值也一起释放。有名称接收的值不适用这条规则：`let one:string = xs[0];` 归 `one` 持有，`console.print(xs[0])` 在打印那一步就释放了。一个式子中连续访问多级容器的，**中间每一步读走的值同样适用这条规则**：`xs[0][0];` 里 `xs[0]` 读走的那个元素、`cs[0].n;` 里 `cs[0]` 拷贝出来的那个值，都在这一句走完时按读走的反序释放 |
| 给一个名称重新赋值 | 被替换掉的旧值当场释放，与覆盖容器的一个位置、覆盖 `class` 的字段遵循同一条规则。`r = r` 这种自身覆盖自身的情况不算（先比较一次句柄）。遍历得到的值和 `export shared` 的名称都不参与这套释放 |
| `export shared` 声明的名称 | 不参与这套释放，存活到进程结束 |
| 向操作系统申请内存但失败 | 抛出错误（10091 号），可以 `catch`；没有被接收时以退出码 `1` 结束 |
| 通过 `null` 引用访问成员 | 抛出错误（10092 号），同样可以 `catch`。不是未定义行为，也不会直接崩溃 |
| 调用层数过深，用完栈 | 输出一行 `出错了（10093）：调用套得太深，栈用完了`，退出码 `1`。遇到这个错误时不释放已经创建的值，也不能 `catch`：释放与捕获都要使用栈。栈的大小是 8 MiB，两种运行方式按同一个数值分配栈 |

## 条件分支与循环的求值方式

- 分支中交出后按“可能已经不属于本地”处理。`if` 的任一条路径把 `x` 交出去，离开 `if` 后再写 `x` 就是编译错误；编译器不判断实际走哪条路径。
- 循环体检查两遍。在 `for` 的循环体里把 `x` 交出，下一轮开头再使用 `x` 时，当场报错。

## null 与判空

`null` 是值不是类型，只有引用类型可以取它。判空只有显式比较这一种写法：`if (x != null)`。没有真值语义：非 `boolean` 的值不能作为条件。

| 事项 | 规则 |
| --- | --- |
| 判空之后 | 在条件成立的分支块里按“不是空”来使用。只对局部变量生效，而且要求从判断到使用之间没有重新赋值 |
| 字段和顶层名称 | 不适用上面这条判空规则：先把字段值交给一个局部变量接收，再对这个局部变量判断 |
| 容器中被读走的位置 | 返回 `null`。再次读取之前先判断；容器进出的完整规则见[容器](/reference/037_containers) |
| 写初值 | `let s:string = null` 是合法的写法；不写初值的 `let s:string` 不被接受，初值一律要写 |
| 作为实参 | 参数位置没有写类型时，单独的 `null` 无法传入；写了类型的参数位置传入 `null` 是合法的。这条规则的完整说明见[函数与调用](/reference/039_functions) |
| 未判断就访问成员 | 运行期抛出错误（10092 号），可以 `catch`。编译器不检查这一步，也不会替读代码的人推断 |

## export shared

顶层的 `let` 属于本文件，不能导出。需要让一份可变的值被多个文件共用时，写 `export shared`：

```nf-frag
export shared log:list<string> = []
```

从所有权的角度看，它只有两条不同：**不参与释放**（随本文件顶层初始化一次，存活到进程结束），**不能交出**（`eat(log)`、`let x = log`、`return log`、`box.add(log)`、`log as object` 都是编译错误，只能就地读写）。

容器里每个位置照常只保存一份值：`let s:string = log[0]` 合法，对应位置此后是 `null`。写法本身和跨文件共用的完整规则见[多个文件](/reference/042_modules)。
