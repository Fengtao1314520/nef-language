# 出错的时候

失败用异常传递：`throw` 抛出，调用方用 `try` 与 `catch` 捕获。抛出的内容永远是一个错误码加一条消息。

## throw

```nf
throw (100, "路径不能是空的")
```

| 事项 | 规则 |
| --- | --- |
| 括号 | 必须有，括号里恰好两个值，错误码在前、消息在后。少一个值、不写括号、抛出其他类型都是编译错误 |
| 语句 | 只作为语句使用，不返回值。`let x:int = throw (1, "a")`、`f(throw (1, "a"))` 都是编译错误（`exit` 遵循同一条规则） |
| 错误码的分段 | `10000` 以上属于语言自己保留的错误码，程序自己的码写在 `0` 到 `9999`。占用语言保留的区段是编译错误 |

## 内建错误

内建错误都发生在运行时，抛出形式与手写 `throw` 完全相同，不是无法捕获的崩溃。表中只有一个错误码无法捕获，下面单独说明：

| 错误情形 | 错误码 |
| --- | --- |
| `int` 运算溢出，或移位量超出范围 | 10021 |
| `int` 除以 `0` | 10022 |
| 下标越界（容器、文本与字节块遵循同一条规则） | 10031 |
| `bytes.new` 请求的字节数为负数 | 10030 |
| `dict` 读取不存在的键 | 10032 |
| 遍历一个容器的同时向这个容器添加或删除元素 | 10033 |
| `as` 拆箱，装箱值里存的不是所请求的类型 | 10011 |
| 文本读不成数字，或者 `math.power` 的指数为负数 | 10012 |
| 转换或运算的结果超出目标类型的范围 | 10013 |
| 向操作系统申请内存失败 | 10091 |
| 拿着 `null` 取成员或调用方法（没判空就 `c.f`、`s[0]`） | 10092 |
| 调用套得太深，把栈用完 | 10093 |

表中只有 10093 无法捕获。栈用完之后，释放已经创建的值和跳回 `catch` 都还要使用栈，而耗尽的正是栈本身。

这个错误只输出一行 `出错了（10093）：调用套得太深，栈用完了`，然后以退出码 `1` 结束。

栈的大小是 8 MiB。运行生成产物与用 `nf 文件.nf` 直接运行，两种方式按同一个数值分配栈，同一份代码在两种方式下到达的深度相同。实测一个递归程序：递归 5 千层正常结束并输出结果，递归 20 万层抛出的就是本节开头那一行输出。

## try / catch

```nf
method read_age(one:string):int {
    return text.to_int(one)
}

let word:string = "三十"

try {
    let n:int = read_age(word)
    console.print(n)
} catch (code, msg) {
    console.print(code, msg)
}
```

```text
10012 文本读不成数字
```

| 事项 | 规则 |
| --- | --- |
| 签名 | 签名不做任何标注。没有 `throws` 一类的记号，编译器也不要求调用方必须捕获 |
| `catch` 的形式 | 只有 `(code, msg)` 一种，错误码与消息一起接收。这两个变量是块内的局部变量，离开该块即失效 |
| 筛选错误码 | 不筛选。任何错误码都进入同一个 `catch`，需要分别处理就在块内写 `if` 或 `switch` |
| `finally` | 没有。作用域结束时自动释放 |
| 重抛 | 把错误码和消息再次 `throw` 即可，没有单独的重抛语法 |

自己 `throw` 的错误码和消息，与内建错误抛出的错误码和消息，在 `catch` 块内看不出区别。

## 抛出去的时候

`throw` 让当前函数当场结束，函数内的局部值按声明的反序释放，与正常执行完毕采用同一套清理流程。随后控制流沿调用栈逐帧向外查找，遇到第一个 `catch` 就执行；找不到就退到调用方那一帧。跨过了哪几帧、每一帧释放哪些值，都写在[值与存放](/reference/038_memory)。

```nf
method one() {
    let a:list<int> = [1, 2, 3]
    let x:int = a[9]              // 在这里抛出：下标越界
    // 下面这一行跑不到
    console.print(x)
}

try {
    one()
} catch (code, msg) {
    console.print(msg)            // 下标越界
}
```

## 没人接

程序终止，屏幕上输出一行，返回给操作系统的退出码是 `1`：

```text
出错了（10031）：下标越界
```

输出里没有文件名，没有行号，也没有调用链。

这些信息要求产物额外携带一张行号对照表，与直接生成机器码的目标相冲突。需要定位就在 `catch` 块里自行打印。

## 退出码

程序如何结束、返回给操作系统的数值是多少，退出码表写在[命令行工具](/tools/059_cli)（编译器自己的退出码也在同一页，两边不要混淆）。这里只说明与错误码有关的两点：

抛出的错误一路无人捕获，返回 `1`；`exit (错误码, 说明)` 返回括号里给出的整数，程序自己的码写在 `0` 到 `9999` 这一段，与 `10000` 以上的语言错误码无关。`exit (0, "跑完了")` 就是正常结束加一条消息。

消息原样输出到屏幕上，前面不加 `出错了（…）：` 这一段：这种格式只用于无人捕获的错误，`exit` 括号里的整数不是错误码。已经创建的局部值照常释放，`exit` 只取消尚未执行的代码。

## 完整码表

`10000` 以上属于语言，程序自己的码写在 `0` 到 `9999`。十一个百位段按类别划分：转换、数值、容器与文本、文件、路径、环境、正则、时间、其余、网络、进程。每段的整百错误码是该段的默认码。

网络段只用 `10100` 到 `10105` 六个错误码；进程段只用 `10110` 到 `10112` 三个错误码，两处的消息里都带上系统给出的原始错误码。

组名与段不是一一对应：`json` 组不占段，值取不到时一律返回 `null`，不抛出任何错误。

| 段 | 各错误码的含义 |
| --- | --- |
| 10010、10011、10012、10013、10014 | 转换：默认码、拆箱类型不符、文本读不成数字（含 `math.power` 的负指数）、结果超出目标类型的值域、文本读不成 base64 |
| 10020、10021、10022 | 数值：默认码、整数溢出（含移位越界）、整数除以 `0` |
| 10030、10031、10032、10033 | 容器、文本与字节块：默认码（`bytes.new` 的字节数为负数）、下标越界、缺键、遍历途中修改容器 |
| 10040、10041、10042、10043、10044、10045、10046、10047 | 文件：默认码、读不到或者删不掉（含删不掉的空目录）、写不进去、目录打不开或者无法读取目录属性、内容不是合法的 UTF-8、属性取不到、无法创建这一级目录、无法重命名 |
| 10050、10051 | 路径：默认码、路径本身不合法 |
| 10060、10061 | 环境变量：默认码、没有这个变量 |
| 10070、10071 | 正则：默认码、表达式写错 |
| 10080 | 时间：只有默认码 |
| 10090、10091、10092、10093 | 其余：默认码、申请不到内存、拿着 `null` 取成员或调用方法、调用套得太深把栈用完 |
| 10100 到 10105 | 网络：默认码、连不上这个地址、等待回应超时、解析不到这个名字、这个地址或端口不可用、这条连接已经不可用 |
| 10110 到 10112 | 进程：默认码（等不到子进程、取不到子进程的退出码）、无法启动子进程、同时运行的子进程用完了一百二十八个位置 |

这张表讲的是段位划分，不是哪些错误码会被抛出。

实际会被抛出的只有三十三个错误码（不含 10093 的“栈用完”，它无法捕获），按组列在下面：

- 转换与数值：10011、10012、10013、10014、10020、10021、10022
- 容器、文本与字节块：10030、10031、10032、10033
- 文件：10041、10042、10043、10044、10045、10046、10047
- 路径、环境、正则：10051、10060、10061、10071
- 其余：10091、10092
- 网络：10101、10102、10103、10104、10105（10100 是该段的默认码，映射不到具体错误码的系统错误都从默认码抛出）
- 进程：10110、10111、10112（前两个的消息里带上系统给出的原始错误码）

十个段的默认码里，实际会抛出的只有四个：`10020` 对应 `math.random` 的范围为空，`10030` 对应 `bytes.new` 的字节数为负数。

`10060` 对应 `environment` 向操作系统提出的请求一次也没有成功，`10110` 对应 `process` 段等不到子进程或者取不到退出码。

剩下六个（10010、10040、10050、10070、10080、10090）只占用段位，一处也没有抛出过。

每个成员分别抛出哪个错误码，写在[标准库总览](/stdlib/044_index)每一组的成员表里；能被 `catch` 捕获这一点，对上面三十三个错误码都成立。

## 编译期报出的错误

能被 `catch` 捕获的只有运行期抛出的错误。类型不匹配、声明缺少类型标注、使用已经交出去的名称、函数存在没有 `return` 的路径、`switch` 漏掉枚举成员又没有写 `default`，这些都发生在编译期，程序不会开始运行。常见的编译错误连同编译器的报错原文列在[错误信息索引](/tools/060_errors)。
