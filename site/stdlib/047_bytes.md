# 字节块

`bytes` 是一段连续内存的字节块：每个位置存一个字节，总长度在 `bytes.new(size)` 这一步确定，创建之后只修改内容，不修改长度。

`bytes` 是语言自带的内建引用类型，遵循[值与存放](/reference/038_memory)里的所有权约定。

同样的内容放进 `list<byte>` 也放得下，只是容器的这种存法每个位置要占 8 个字节：5,607,424 个字节的数据要占 98,205,840 个字节。

`bytes` 没有这笔额外开销，占多少内存就用多少内存。

`bytes` 不校验编码：字节块里放着的只是字节，这串字节是不是合法的 UTF-8，类型本身不过问。

校验发生在把字节转换成文本的时刻：`text.from_bytes` 转换前要过一次 UTF-8 校验，不合法时抛 10044 号；`bytes.from_base64` 解出的字节不做校验，因为这一条路径接收的就是二进制本身。

与 `string` 的分工按用途划分：要做计算、存进文件、通过网络发送出去，用 `bytes`；要把内容当作文本继续读取，先用 `text.from_bytes` 转换成 `string`。

`text.to_bytes`、`text.from_bytes`（[文本处理](/stdlib/046_text)）与 `file.read_bytes`、`file.write_bytes`（[读写文件](/stdlib/050_file)）返回和接收的都是 `bytes`。

| 写法 | 返回 | 抛出的错误码 | 说明 |
| --- | --- | --- | --- |
| `bytes.new(size)` | `bytes` | 10030 | 创建一块指定长度的字节块，内容先全部置零。长度为负数时抛 10030 号（`bytes.new 要的字节数不能是负数`） |
| `length(value)` | `int` | 不抛 | 返回字节的个数。与三种容器、文本的写法相同，不是点号成员 |
| `b[i]` | `byte` | 10031 | 读取第 i 个字节，取值 0 到 255。越界抛 10031 号（`下标越界`），容器与文本越界时抛出的也是这个错误码 |
| `b[i] = 字节` | 没有 | 10031 | 把一个字节写入指定位置。写 `300` 这类超出 0 到 255 的字面量，编译期就会拒绝；写整数变量要先 `as byte`，不会自动转换 |
| `b.slice(start, end)` | `bytes` | 10031 | 截取一段并另外创建一块字节块，含起点、不含终点。边界判断与 `list.slice`、`string.slice` 完全相同：起点为负、`end` 超出长度、`start > end` 都抛 10031 号；`start == end` 返回空的字节块 |
| `b.to_base64()` | `string` | 不抛 | 把这一块字节按 RFC 4648 的标准表写成 Base64 编码文本。用的表与 `=` 补齐方式和 `text.to_base64` 完全相同，区别只在来源是字节而不是文本；返回文本，因为 Base64 编码写出来就是给人阅读或者写进 JSON 的字符。空的字节块返回空文本 |
| `bytes.from_base64(encoded)` | `bytes` | 10014 | `b.to_base64()` 的反向操作。外形上的三条检查与文本一侧完全相同（长度是否为整数倍、`=` 的位置、字符是否在字母表内），不符合时抛出的也是 10014 号，报错原文一句不差。**只有一处不同**：解出来的字节不校验编码，这一条处理的就是二进制数据，`/w==` 解出的 `255` 在这里是内容而不是错误，所以 10044 号在这条路径上永远不会抛出 |
| `bytes.join(parts)` | `bytes` | 10092 | 把列表里的多块字节按顺序拼接成一块新的，中间不插入任何内容。字节块的长度确定之后不再增减，而网络上一段一段接收的数据需要连续存放，这个函数就是用来把两块合并成一块的。列表中任一元素为空句柄时抛 10092 号，`text.join` 遇到空句柄时抛出的也是这个错误码；空列表返回空的字节块。要插入分隔符，就把分隔符也做成一块字节放进列表 |

输出形如 `[65, 255, 0]`：每个位置输出一个十进制数，空的字节块输出 `[]`。

在 `null` 句柄上调用方法抛 10092 号，直接输出一个空句柄得到 `null`，这两条与三种容器的规则相同。

## 所有权与相等比较

把一个字节块交给一个名字、放进列表的一个位置、写进类的字段，都会发生交出；名字执行到尽头，这块字节就归还给堆。

判断相等比较的是“是不是同一块字节”，不比较内容：要比较内容得自己写一段循环，这一点与三种容器相同。

`bytes` 句柄装不进盒子（`b as object` 是编译错误），也不能作为字典的键与集合的成员。

句柄比较的是身份，不是内容。

散列值要随内容保持稳定，而字节块的内容还能修改，所以 `bytes` 句柄既装不进盒子，也不能当字典的键。

## 创建、写入与截取

```nf
let head:bytes = bytes.new(4)
head[0] = 72
head[1] = 105
console.print(length(head), head)
let cut:bytes = head.slice(0, 2)
console.print(cut)
console.print(text.from_bytes(cut))
```

```text
4 [72, 105, 0, 0]
[72, 105]
Hi
```

## Base64 编码与拼接

要把一块字节写成能放进 JSON 的 Base64 编码字符，调用 `to_base64()`；反过来把编码好的文本读取回一块字节，用 `bytes.from_base64`。

把两块合并成一块用 `bytes.join`：网络上一段一段接收的数据要连续存放，靠的就是这个函数。

```nf
let b:bytes = "甲a".to_bytes()
console.print(b.to_base64(), bytes.from_base64("/w=="))
let first:bytes = b.slice(0, 3)
let rest:bytes = b.slice(3, 4)
console.print(bytes.join([first, rest]))
console.print(bytes.join([]))
```

```text
55SyYQ== [255]
[231, 148, 178, 97]
[]
```

`bytes.from_base64` 解出来的字节不校验编码：`/w==` 解出的 `255` 在这里是一块字节序列里的内容。

同样的文本用 `text.from_base64` 解码，就要过一次 UTF-8 校验，校验不过抛出 10044 号错误。

选择哪一种由编写者决定：要做计算、存进文件、发送出去，选 `bytes`；要当作文本继续读取，选 `text.from_base64`。

## 按位置遍历

要依次访问每一个位置，用带下标的计数循环：`for (i:int in 0 until length(b))`。

`for (x:byte in b)` 这种写法不支持：能按位置遍历的四种类型是三种容器与文本。
