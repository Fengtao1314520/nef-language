# 进程

这一组叫 `process`，负责三件事：**启动、等待、不再等待时结束子进程**。这些都是语言之外的事：运行另一个程序、查看另一个程序返回的退出码，或者启动一个带调试端口的浏览器并等待连接。

`process.start` 创建一个 `Process` 句柄，`wait()` 与 `close()` 这两个方法在这个句柄上调用。

子进程写到屏幕上的内容不经过语言，直接输出到屏幕上；要把子进程的输出读取到程序里，这一组没有提供对应的函数。

| 写法 | 返回 | 抛出的错误码 | 说明 |
| --- | --- | --- | --- |
| `process.start(command_line)` | `Process` | 10111 | 启动一个程序。这条命令行**原样**交给系统：语言不负责拆分参数，也不负责添加引号，所以路径里带空格时自己写成 `"C:/Program Files/…/chrome.exe"`，参数之间用一个空格隔开。命令行是空字符串、长度超过内部缓冲区，或者系统拒绝启动时，都抛 10111 号（`起不来那个程序`），消息里带上系统给出的原始错误码 |
| `p.wait()` | `int` | 10110、10092 | 一直等到子进程运行结束，返回子进程的退出码。语言不代替使用者判断“0 才算成功”，要判断就自己写 `if (p.wait() != 0)`。等待失败、或者读取不到退出码时抛 10110 号（`等不到那个程序`、`问不到那个程序的退出码`），消息里也带上系统给出的原始错误码。句柄已经失效时是 10092 号 |
| `p.close()` | 没有 | 不抛 | 不再等待：子进程还在运行就把它结束，关闭句柄，这个名字当场变成空句柄。对已经运行结束的进程再调用一次也没有影响：系统只返回“这个进程已经结束了”这句话，这个函数不检查系统的返回值 |

```nf
let p:Process = process.start("cmd.exe /c exit 3")
console.print(p)
console.print(p.wait())
let q:Process = process.start("cmd.exe /c ping -n 30 127.0.0.1")
q.close()
```

```text
Process
3
```

## 退出码要自己判断

`p.wait()` 返回子进程自己的退出码，语言不代替使用者判断“0 才算成功”：要判断成功与否，就自己写 `if (p.wait() != 0)`。

等待失败、或者读取不到退出码时抛 10110 号，消息里带上系统给出的原始错误码。句柄已经失效时抛 10092 号。

## 句柄的三处特别之处

`Process` 与 [TCP 套接字](/stdlib/057_net)中的 `Socket`、`Listener` 属于同一类：这三个类型对应的都是操作系统给出的资源，不是堆上的一块内存。一个 `Process` 同样只有一个持有者，名字执行到尽头时由语言回收一次。

直接输出一个 `Process` 句柄时，打印出来的是类型名 `Process`：进程编号由系统分配，每次运行都不同，输出编号没有意义。

`Process` 既不能放进列表，也不能装箱。

第三处是名字执行到尽头时语言做的回收：**没有等待过的子进程直接结束**。

`close()` 只用来提前回收，回收之后这个名字就是空句柄。

对已经运行结束的进程再调用一次 `close()` 也没有影响：系统只返回一句“这个进程已经结束了”，`close()` 不检查系统的返回值。

## 同时最多运行一百二十八个

句柄里存的数字不是系统给出的句柄：一个子进程在系统那里有进程句柄与线程句柄两个句柄，一个名字装不下两个句柄，所以语言把进程句柄存进自己的一张一百二十八项的表里，变量拿到的是进程句柄在这张表里的位置。

表满即上限：同时运行的子进程有一百二十八个，超出上限时抛 10112 号（`同时跑着的子进程太多了，这一张表用完了`）。

三个标准流（输入、输出、错误）都不接管；子进程沿用调用方当前的工作目录与环境变量。

要换一个目录启动子进程、或者把子进程的输出读取回程序，这一组没有提供这两种写法。
