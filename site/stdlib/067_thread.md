# 线程

这一组叫 `thread`，负责两件事：**起一条线程跑一个函数**、**等它跑完取回结果**。

语言里没有锁、没有条件变量、没有共享的可变内存。一条线程跑的那一个函数收一个值、返回一个值，两边的来往只有这一次交出与这一次取回。

`thread.start` 创建一个 `Thread` 句柄，尖括号里写的是被起的那个函数的返回类型。`wait()` 与 `id()` 这两个方法在这个句柄上调用。

| 写法 | 返回 | 抛出的错误码 | 说明 |
| --- | --- | --- | --- |
| `thread.start(worker, argument)` | `Thread<T>` | 10095、10096 | 起一条线程跑那一个函数，返回一张句柄（`Thread<int>`、`Thread<string>` 这一种，尖括号里是被起的那个函数的返回类型）。第一个入参要么是一个写出来的顶层函数名，要么是一个 `fn` 名字；那一个函数只收一个参数、必须有返回值，第二个入参就是交给它的那一个值。交进去的那个值按“交出”处理：原来那个名字当场作废。能交过去的类型只有不参与递归析构的那几样——值类型、文本与 `class` 句柄；容器、`bytes`、JSON 的值、盒子、系统句柄与函数值（第一个入参那个位置除外）都在编译期拦下，理由是它们的归还点还没按线程各一份定下来。同时挂着的线程到一百二十八条时报 10095 号，系统起不出这条线程报 10096 号并带上系统号码 |
| `Thread.wait()` | `T` | 10094、10092 | 等那条线程跑完，返回它那个函数返回的值。等到的是“那条线程出错结束了”（它的抛出没人接住）时当场抛 10094 号那一句——那一条线程自己那一句“出错了…”与它的调用链已经先打过了。等过一次之后这个名字就是空句柄，再等一次是 10092 号。名字走到作用域尽头时不需要写这一句：语言自动等一次并归还那条线程的运行期状态，那一次自动等不抛 10094 |
| `Thread.id()` | `int` | 不抛 | 返回那张线程表上的位置。它只是给人看的编号（排查、打印时用），不能拿来等那条线程——等它只走 `Thread.wait()` |

```nf
method double(n:int):int {
    return n * 2
}
let t:Thread<int> = thread.start(double, 21)
console.print(t.wait())
```

```text
42
```

## 起线程那一处要的是什么

被起的那个函数写在文件顶层，收一个参数，返回一个值。

两个限制都在编译期说。一张线程表里只留得下一个位置放实参；句柄身上那一个尖括号参数要有出处，它写的就是那个函数的返回类型。

第一个入参写函数名，也写 `fn` 类型的名字：

```nf
method work(n:int):int {
    return n + 1
}
method use(job:fn(int):int, v:int):Thread<int> {
    return thread.start(job, v)
}
let f:fn(int):int = work
let t:Thread<int> = use(f, 41)
console.print(t.wait())
```

```text
42
```

泛型的顶层函数不能直接交出去，那一句拒绝是“`twice` 是泛型，先填尖括号里的类型再交出去”。原因和上面那一条是同一件事：那一只实例要填什么类型，是从实参推出来的，而 `thread.start` 的第一个位置一个实参也拿不到。所以先写一个不带尖括号的函数把类型定下来，交那一个：

```nf
method twice<Element>(v:Element):Element {
    return v
}
method step(n:int):int {
    return twice(n) + 1
}
let t:Thread<int> = thread.start(step, 41)
console.print(t.wait())
```

```text
42
```

写 `thread.start(twice<int>, 41)` 不行：尖括号只在后面紧跟左括号或左花括号时才当成类型实参收，这一处过不去，编译器在那里报的是 `这里不该出现 ","`。

## 交进去的值按“交出”处理

`thread.start` 的第二个入参与递给普通函数不同：值类型与文本是拷贝，`class` 句柄是交出。

交出之后原来那个名字不再持有那一个对象，再写它就是“这个名字已经交出去了”那一句。

这样定是因为两条线程同时读同一块内存需要锁，而语言不提供锁。把交出记在起线程的这一处，一块内存同一时刻就只有一个持有者。

```nf
class Count {
    n:int
}
method build(box:Count):int {
    box.n = box.n + 1
    return box.n
}
let c:Count = new Count(n: 41)
let t:Thread<int> = thread.start(build, c)
console.print(t.wait())
```

```text
42
```

这几类交不过去，编译期就拦下：`list`、`dict`、`hashset`、`bytes`、JSON 的值、盒子、四种系统句柄与函数值。

理由是它们的归还点还是全程序共用的一处，两条线程同时用到同一块就会互相踩。

## 没有 `close()`：名字走到尽头自动等一次

`Thread` 只有 `wait()` 与 `id()`，没有“不等了”的写法。

名字执行到作用域尽头时，语言自动等那一条线程跑完，再归还它那份运行期状态：它自己那一块状态内存，与它在系统那一头的句柄。

这一条与[进程](/stdlib/053_process)相反：子进程走到尽头时不等待、直接结束，线程走到尽头时一定等到它跑完。

因为线程的返回值由它自己那条栈上的帧算出来。不等它就取不到那个值，也归还不了那一块。

不写 `wait()` 的程序也是对的：名字走到所在那一段的尽头时语言等一次，所以下面这两行的先后每回相同。

```nf
method greet(part:string):int {
    console.print("甲" + part)
    return 0
}
method leave() {
    let t:Thread<int> = thread.start(greet, "号")
}
leave()
console.print("这一行一定排在上面那一行后面")
```

```text
甲号
这一行一定排在上面那一行后面
```

## 那一条线程自己出错

被起的那个函数里的抛出没人接住时，只结束那一条线程。

屏幕上打的是那一条线程的“出错了…”那一句与它的调用链。整个程序继续跑，起它的那一条不受影响。

等到它跑完时读到的那个错误号，变成主线程这一次的抛出（10094 号），所以这一句可以按现成的 `catch` 接住：

```nf
method inner(n:int):int {
    return text.to_int("不是数字")
}
method outer(n:int):int {
    return inner(n) + 1
}
let t:Thread<int> = thread.start(outer, 1)
try {
    console.print(t.wait())
} catch (code, msg, at) {
    console.print("接住了，错误号", code)
}
```

屏幕上先出现的是那一条线程自己那一句，下面跟着它自己的调用链，一行一层。链从它那一帧往外走，走到 `@thread_begin` 就停——那一段是运行期的代码，不在检查点表里。

被起的那个函数里只有一层抛出时链上是空的：一项也没捕获到就一个字节也不发，屏幕上只有那一句“出错了…”。

```text
出错了（10012）：文本读不成数字（在 worker.nf 2:17）
    worker.nf 2:17 inner
    worker.nf 5:12 outer
接住了，错误号 10094
```

## 同时最多一百二十八条

线程句柄里存的数字不是系统给的句柄：它是运行期那张一百二十八项的表里的位置，与[进程](/stdlib/053_process)那一档同一做法。超出上限时抛 10095 号（`同时跑着的线程太多了，这一张表用完了`）。

每一条线程有自己的一份运行期状态：它自己的抛出处理链、调用链捕获，以及文件、网络各处那些临时位置。栈也各自一条。

堆只有一份，由运行期内部加锁护住。

两条线程同时往屏幕上打印时，一行不会被拆成两截：攒在该线程那一截缓冲里的字整行交出去之后，才轮到别人。

## 调试只跟着程序自己那一条线程

按 F5 调试时，断点、单步、调用栈与变量都只给程序自己那一条线程。`thread.start` 起的那一条线程走到同一行上不会停。那一行仍然标成已验证，因为可停的位置确实在。

要看那一条线程在做什么，把 `console.print` 写进它跑的那个函数；或者在它返回之后用 `wait()` 把结果拿到自己这一头看。
