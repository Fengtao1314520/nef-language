# 编辑器与调试

装好扩展之后，打开 `.nf` 文件就有语法高亮、错误波浪线、补全与悬停，按 F5 可以单步调试。

扩展自己不实现第二套规则：报错、补全、悬停都问 `nf lsp`，调试器把 `nf dap` 当作调试适配器启动。编辑器里看到的那句报错，与命令行上 `nf check` 打出来的是同一句原文。

## 安装

扩展在仓库的 `vscode/` 目录里，先生成安装包：

```text
cd vscode
npm install
npm run package
```

产物是 `vscode/nef-0.4.1.vsix`，文件名里的号跟着插件版本走。在 VS Code 的扩展面板里点右上角的 `...`，选“从 VSIX 安装”，指到这个文件。要求 VS Code 1.90 以上。

打包进去的还有一份 `nf.exe`（Windows x64），放在扩展目录的 `server/` 下，语言服务器与调试器用的都是它。

要用本机自己编译的版本，就在设置里填 `nf.path`：填了就优先用填进去的那条路径，语言服务器与调试器一起换。这一项留空时，用的是扩展自带的那份可执行文件。

## 高亮与波浪线

语法高亮、注释符号与括号配对不经过扩展的代码：它们写在 `syntaxes/nf.tmLanguage.json` 与 `language-configuration.json` 里，由 VS Code 自己完成。

这张记号表与编译器的词法分析由站点的检查脚本逐块比对，两边不会走偏（[命令行工具](/tools/059_cli)的 `nf tokens` 一节写的是同一件事）。

波浪线在两个时候重算：打开文件、每次改动。改动不必先保存才会更新。出错的字符下面画线，把鼠标停在上面能看到编译器那句原文，前面带着第几行第几列。

词法或语法没过时只报最先出现的一条，与命令行上 `nf check` 的停止条件相同：修正一句才看见下一句。

## 补全

输入点号，或者在名字的位置按 `Ctrl`+`Space`，会列出候选。四类来源：

| 打的位置 | 列出来的是什么 |
| --- | --- |
| `page.` 这类点号后面 | 这个值的成员；句柄与容器也算 |
| `console.` 这类标准库组名后面 | 那一组里的函数与常量 |
| `wt.` 这类包的挂名后面 | 那个包里 `export` 出去的名字；没写 `export` 的不列 |
| 行首 | 本文件里写过的名字、引进来的名字、这一趟认识的类型名、标准库的组名、关键字与内建名 |

补全项右边那一栏写着它的签名或种类名。带签名的那些一律写成编程语言的样子：参数名是英文小写加下划线，只读借用的那一个写成 `ref 名字: 类型`，变长参数写 `(...values)`，元素类型跟着接收者走、写不出真类型时用 `T`、`K`、`V`，没有返回值的动作不写冒号后面那一段。

一句写到一半也能问：`page.` 后面还什么都没有时，`nf lsp` 在光标处插一个占位名字再走一遍检查，好让点号左边那一段先算出类型。这个占位名字只为这一次问答存在，不会出现在编辑器里，也不会写进文件。

跳转定义没有开。要看一个名字定义在哪儿，目前还是用查找。

## 悬停

鼠标停在名字上，弹出来的内容分三段：

1. 第一行是签名或者类型，比如 `step(label: string)`、`let page: Page`。
2. 接着是写在声明上面的注释：中文那一段、以 `en:` 起头的英文那一段。
3. 最后是一段标着 `nf` 的示例，来自注释里以 `例：` 起头的那一段。

注释的三段写法在[应用与入口](/learn/022_start)里教过。没有写注释的名字，弹出来就只有第一行那一句。

## 调试

打开一份 `.nf` 按 F5。没有 `launch.json` 也可以：扩展会把当前编辑器里那份文件填成 `program`。要固定下来就自己写一份，两个字段：

```json
{
  "type": "nf",
  "request": "launch",
  "name": "调试一份示例",
  "program": "samples/linecount.nf",
  "args": ["samples/shopping.nf"]
}
```

`args` 传进程序里的 `args` 数组，与命令行上直接运行是同一份；上面这一组就是 `nf samples/linecount.nf samples/shopping.nf`。路径按工作区根目录算。

`program` 说的是哪一份 `.nf`，不给这一项会报 `launch 里没给 program：要调试得说清哪一份 .nf`。

调试面板上能做的事：

| 动作 | 背后是什么 |
| --- | --- |
| 断点 | 按行号下；一行一个，编译器认可的位置会标成已验证 |
| 继续、暂停 | 让被调起来的那条线程跑起来或停在安全点 |
| 单步、步入、步出 | 三条都走，停在下一处时帧与变量的读数一起刷新 |
| 调用栈 | 从停住的那一帧往外列 |
| 变量 | 一帧两个作用域：这一帧的“局部”，与顶层名字住的那一批“静态”。停在文件顶层时只看“局部”是空的，`let` 的名字在“静态”里 |
| 悬停查看变量的值 | 与调试面板同一套读法，读的是被调试进程当前的栈 |
| 内存视图 | 给出地址就能看那块字节，变量项带着一份内存引用 |
| 程序的输出与退出码 | 走调试控制台；标准输出与标准错误各带来源送进来，两条流的分法与命令行上直接运行相同 |

条件断点与命中次数不支持：协议里那两个字段会被忽略，只按行号下断点。也不提供运行中改变变量的值，以及往回单步。

调试用的检查规则与 `nf check` 完全相同，不会出现在编辑器里没报错、按 F5 却报另一套话的情况。

## 未提供的能力

- 没有跳转定义、找引用、重命名符号与格式化。
- 没有代码片段（snippet），`for`、`method` 这些骨架要自己写。
- 没有工作区级别的名字索引：补全列出的是本文件与 `import` 引进来的那些名字，不做跨目录的模糊搜索。
- 诊断只在打开与改动这两个时候算，没有后台定时重算，也没有改一个文件就让用到它的另一个文件跟着重算：改了一个被引入的文件，另一个用到它的文件要自己动一下才会重算。
