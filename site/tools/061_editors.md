# 编辑器与调试

装好扩展之后，打开 `.nf` 文件就有语法高亮、错误波浪线、补全、悬停、参数提示、大纲与折叠，按 F12 跳到定义，按 F5 可以单步调试。

扩展自己不实现第二套规则：报错、补全、悬停都问 `nf lsp`，调试器把 `nf dap` 当作调试适配器启动。编辑器里看到的那句报错，与命令行上 `nf check` 打出来的是同一句原文。

## 安装

扩展不带编译器，语言服务器与调试器用的都是本机那一份 `nf`，所以先生成编译器，再生成安装包：

```text
cd compiler
go build -o ../nf.exe ./cmd/nf
cd ../vscode
npm install
npm run package
```

前一条的产物是仓库根的 `nf.exe`（Windows x64），后一条的产物是 `vscode/nef-0.5.5.vsix`，文件名里的号跟着插件版本走。要求 VS Code 1.90 以上。

在 VS Code 的扩展面板里点右上角的 `...`，选“从 VSIX 安装”，指到这个文件。

装完要告诉扩展用哪一份编译器，两种写法任选一种：设置里填 `nf.path`，语言服务器与调试器都走这一份。

```json
{
  "nf.path": "C:/Work/nf/nf.exe"
}
```

这一项留空时，扩展按 `PATH` 里的 `nf` 找，把 `nf.exe` 所在的目录加进 `PATH` 也一样能用。两处都没有时语言服务器起不来：插件窗口说明去哪里填，并给一个直接跳到 `nf.path` 这一项的按钮。

改过编译器之后重新 `go build`，在 VS Code 里重载窗口就换成新的一份，不必重新打包扩展。屏幕上说话的那一份，与命令行 `nf version` 打印的是同一份。

## 高亮与波浪线

语法高亮、注释符号与括号配对不经过扩展的代码：它们写在 `syntaxes/nf.tmLanguage.json` 与 `language-configuration.json` 里，由 VS Code 自己完成。

这张记号表与编译器的词法分析由站点的检查脚本逐块比对，两边不会走偏（[命令行工具](/tools/059_cli)的 `nf tokens` 一节写的是同一件事）。

记号表分得开的是字面上的那一类：关键字、内建类型名与组名、自己写的类型名、方法名与函数名、参数与字段、字符串与转义、数字、行注释与块注释。括号、逗号、冒号、分号与点号走的是标点那一档，主题一般按正文前景画，不再和运算符挤成同一个颜色。

字面分不开的那一些交给语义着色：`twice(1)` 里的是调用、`method twice(...)` 里的是定义，`n` 是参数还是局部量，`o.body` 里的 `body` 是字段。

语言服务器把每一个名字报成类型、函数、方法、参数、字段、变量或常量，报的依据与悬停、跳转定义是同一套账，不会两处各说一套。

点号后面那一个名字问的是检查器认成员那一步的答复，不是括号的位置：自己写的字段后面就算跟了左括号（那一句编译不过），屏幕上仍然是字段那一档；枚举的成员报成成员，包里导出的数报成常量。鼠标停在点号后面的名字上，悬停在签名后面再说一句它属于哪一个类型、组或包。

波浪线在两个时候重算：打开文件、每次改动。改动不必先保存才会更新。出错的字符下面画线，把鼠标停在上面能看到编译器那句原文，前面带着第几行第几列。

词法或语法没过时只报最先出现的一条，与命令行上 `nf check` 的停止条件相同：修正一句才看见下一句。

## 补全

输入点号，或者在名字的位置按 `Ctrl`+`Space`，会列出候选。四类来源：

| 打的位置 | 列出来的是什么 |
| --- | --- |
| `page.` 这类点号后面 | 这个值的成员；句柄与容器也算 |
| `console.` 这类标准库组名后面 | 那一组里的函数与常量 |
| `wt.` 这类包的别名后面 | 那个包里 `export` 出去的名字；没写 `export` 的不列 |
| 行首 | 本文件里写过的名字、引进来的名字、这一趟认识的类型名、标准库的组名、关键字与内建名 |

补全项右边那一栏写着它的签名或种类名。带签名的那些一律写成编程语言的样子：参数名是英文小写加下划线，只读借用的那一个写成 `ref 名字: 类型`，变长参数写 `(...values)`，元素类型跟着接收者走、写不出真类型时用 `T`、`K`、`V`，没有返回值的动作不写冒号后面那一段。

一句写到一半也能问：`page.` 后面还什么都没有时，`nf lsp` 在光标处插一个占位名字再走一遍检查，好让点号左边那一段先算出类型。这个占位名字只为这一次问答存在，不会出现在编辑器里，也不会写进文件。

名字定义在哪一行，用 F12 跳过去，见下面[跳转定义](#跳转定义)那一节。

## 悬停

鼠标停在名字上，弹出来的内容分三段：

1. 第一行是签名或者类型，比如 `step(label: string)`、`let page: Page`。
2. 接着是写在声明上面的注释：中文那一段、以 `en:` 起头的英文那一段。
3. 最后是一段标着 `nf` 的示例，来自注释里以 `例：` 起头的那一段。

注释的三段写法在[应用与入口](/learn/022_start)里教过。没有写注释的名字，弹出来就只有第一行那一句。

## 参数提示

写到调用的括号里就会问：打到左括号或者逗号之后，弹出来的是这一条的签名，光标所在的那一个参数在签名里被标出来。

自己写的函数与方法、标准库组的动作、具体容器上的成员用的是同一张签名表。`xs.add(2)` 里 `xs` 是 `list<int>`，提示就写 `list.add(value: int)`，元素类型跟着那一只容器走，不写成 `T`；说不出真类型的那些才写 `T`、`K`、`V`。

变长参数只有一处可标：`console.print(...values)` 写多少个实参都标在那一处。认不出被叫的是谁时不显示，也不猜一行。

## 大纲与折叠

`Ctrl`+`Shift`+`O`（或者点开编辑器顶上的面包屑）列出这一份文件里的类型、函数与常量；类型身上的字段与方法排在下一层，输入几个字母就在其中筛。

左侧行号旁的折叠箭头按同一棵树来：每个类型、方法、函数各一段，连着两行以上的行注释一段，跨行的块注释一段，开头那一串 `import` 合成一段。

两处看的是编译器认得出的结构。括号还没闭合的文本先补上右括号再算，所以 `class Note {` 底下正敲着也能列出大纲；补不出来的那一种（字符串没有闭合）这两样暂时没有，语法文件给的那套着色不受影响。

补括号只为了让编辑器有东西可显示：波浪线仍以原文为准，`nf check` 与编译不会因此放过那一处没闭合。

## 调试

打开一份 `.nf` 按 F5。没有 `launch.json` 也可以：扩展会把当前编辑器里那份文件填成 `program`。要固定下来就自己写一份，两个字段：

```json
{
  "type": "nf",
  "request": "launch",
  "name": "调试一份示例",
  "program": "samples/linecount.nf",
  "args": ["samples/shopping.nf"]
}
```

`args` 传进程序里的 `args` 数组，与命令行上直接运行是同一份；上面这一组就是 `nf samples/linecount.nf samples/shopping.nf`。路径按工作区根目录算。

扩展包里带一份写好的 `examples/launch.json`：三段配置，分别是当前打开的文件、带参数的示例、把 `breakOnThrow` 写成 `true` 的那一段，每一段上面有中文与英文两句说明。复制进工程的 `.vscode/launch.json` 就能用。

`program` 说的是哪一份 `.nf`，不给这一项会报 `launch 里没给 program：要调试得说清哪一份 .nf`。

调试面板上能做的事：

| 动作 | 背后是什么 |
| --- | --- |
| 断点 | 按行号下；一行一个，编译器认可的位置会标成已验证 |
| 继续、暂停 | 让被调起来的那条线程跑起来或停在安全点 |
| 单步、步入、步出 | 三条都走，停在下一处时帧与变量的读数一起刷新 |
| 抛出时停下 | 开关是 `launch.json` 里的 `breakOnThrow`，默认关着；开了只在没人接住的那一次停 |
| 调用栈 | 从停住的那一帧往外列 |
| 变量 | 一帧两个作用域：这一帧的“局部”，与顶层名字住的那一批“静态”。停在文件顶层时只看“局部”是空的，`let` 的名字在“静态”里 |
| 悬停查看变量的值 | 与调试面板同一套读法，读的是被调试进程当前的栈；值后面跟着这个名字写下的地方上面那一段注释 |
| 内存视图 | 给出地址就能看那块字节，变量项带着一份内存引用 |
| 程序的输出与退出码 | 走调试控制台；标准输出与标准错误各带来源送进来，两条流的分法与命令行上直接运行相同 |

停在断点上时把变量名直接写在句子里也能看到值：打开用户设置 `debug.inlineValues`，每句里的变量名后面就跟着它当前的值。

条件断点与命中次数不支持：协议里那两个字段会被忽略，只按行号下断点。也不提供运行中改变变量的值，以及往回单步。

抛出停下来要在 `launch.json` 里把 `breakOnThrow` 写成 `true`。开了之后，只有没人接住的那一次抛出会停下来：程序停在抛出那一句上，调用栈与每一帧的变量都读得出来，因为栈还没往外走。

有人接住的那一次不停，那一种现场要自己在 `catch` 那一行下断点才看得到。开关关着（默认）时，抛出照常一路往外找接住它的那一段。

一条抛出只问一次。写了 `try` 与 `finally` 但没写 `catch` 的那一种，`finally` 那一段自己不算接住它，程序停在这一段跑完、要把那一条接着往外送的那一句上，不是停在最里那一处抛出；栈里从这一层往外的每一帧照旧读得出来。

调试用的检查规则与 `nf check` 完全相同，不会出现在编辑器里没报错、按 F5 却报另一套话的情况。

## 跳转定义

在名字上按 F12，或者用右键菜单里的“转到定义”，会跳到它写下的那一行：自己写的函数、方法、字段、顶层与局部的 `let`、类型名，以及 `import` 引进来的名字，都能跳到定义它的那一行。落到的是那一行的开头，不框住名字本身。

跳不到的那些如实跳不到：标准库的动作（`text.to_int`、`xs.add`）没有写在源码里的一行，内建类型名与组名同理，光标停在它们上面对编辑器不会跳转，也不会跳到一个错的地方。

## 未提供的能力

- 没有找引用、重命名符号与格式化。
- 没有代码片段（snippet），`for`、`method` 这些骨架要自己写。
- 没有工作区级别的名字索引：补全列出的是本文件与 `import` 引进来的那些名字，不做跨目录的模糊搜索。
- 诊断只在打开与改动这两个时候算，没有后台定时重算，也没有改一个文件就让用到它的另一个文件跟着重算：改了一个被引入的文件，另一个用到它的文件要自己动一下才会重算。
