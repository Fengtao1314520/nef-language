# nf

nf 语言在 Visual Studio Code 里的编辑器支持。装好之后打开 `.nf` 文件就有语法高亮、编译期错误提示、补全、悬停、按 F12 转到定义、找引用、重命名、格式化文档、参数提示、大纲与折叠；按 F5 可以调试。

分析与报错都出自 `nf` 编译器：扩展把它作为语言服务器（`nf lsp`）启动，把它的调试适配器（`nf dap`）作为 DAP 服务端启动，自己不实现第二套规则。

## 功能与用法

| 功能 | 怎么触发 | 屏幕上是什么 |
| --- | --- | --- |
| 语法高亮 | 打开 `.nf` 文件 | 关键字、控制流、运算符、数字（十进制与十六进制）、字符串与转义、注释各成一档；类型名、函数名、方法名、参数、字段与局部量再各自分档（下面「语义着色」那一条） |
| 错误提示 | 文本每次改动之后重新算，不必保存 | 出错的字符下面画波浪线，鼠标停上去显示 `nf check` 的那句原文与行列位置 |
| 补全 | 输入 `.`，或在名字位置按 Ctrl+Space | 这个值的成员、标准库组里的函数、包里 `export` 出去的名字、本文件与引进来的名字、类型名与关键字；右边那一栏是这一条的签名 |
| 悬停 | 鼠标停在一个名字上 | 第一行是签名或类型，点号后面的名字后面再说一句它属于哪一个类型、组或包；第二行起是写在声明上面的注释：中文一段、英文一段、一段标着 nf 的示例 |
| 转到定义 | 光标停在名字上按 F12，或用右键菜单里的“转到定义”| 跳到那一个名字写下的那一行，包括 `import` 引进来的名字；落在行首，认不出来的时候不跳也不跳错地方 |
| 找引用 | 光标停在名字上按 Shift+F12，或右键菜单里的“转到引用” | 列出这个名字写过的每一处：声明、读写、调用、类型标注与 `import` 那一行，跨文件的也在内；泛型的模板与实例归并成同一个符号，接口的方法带上 `base` 链上同名的那一家 |
| 重命名 | 光标停在名字上按 F2 | 把找引用列出的每一处一起换成新名字；新名字是关键字、内建名字或改完编译不过时拒绝并说明原因，包容器（`.nfpack`）里的名字只读 |
| 格式化文档 | Shift+Alt+F，或右键菜单里的“格式化文档” | 缩进按花括号深度重排，记号之间的空白收齐，连续空行并成一行，行尾空白去掉；字符串、字符与注释的原文不动，缩进宽度与空格还是制表符跟编辑器的设置走 |
| 参数提示 | 打到调用括号的左括号或逗号后面 | 弹出那一行签名，并把光标所在的那一个参数标出来；标准库的动作与库里的方法同一套答复 |
| 大纲 | Ctrl+Shift+O，或点开面包屑 | 这一份文件里的类型、函数与常量，类型身上的字段与方法排在下一层；输入几个字母就在其中筛 |
| 折叠 | 行号左侧的折叠箭头 | 类、接口、枚举、函数与方法各折一段，连着的行注释与跨行的块注释各折一段，开头的 `import` 合成一段 |
| 语义着色 | 打开 `.nf` 文件就有 | 语言服务器把每一个名字报成类型、函数、方法、参数、字段或变量，同一主题下这些档各有自己的颜色；语法文件认不出的那一些区分（声明与调用、参数与局部量）由它补。点号后面那一个名字问的是检查器认成员的答复：字段带上了括号仍然是字段，枚举的成员与包里导出的数各报自己那一档 |
| 调试 | 打开一份 `.nf` 按 F5 | 断点、单步、调用栈、变量、悬停查看变量的值与它上面那段注释、内存视图、程序的输出与退出码 |

## 补全

下面几行是从 `webtest/cases/login.nf` 里实测的答复：左边是当时打的字与补出来的那个名字，右边那一栏是它的签名（不是动作的那几类就写它自己是什么）。

```text
run. 里的 step         step(label: string)
page. 里的 click_at    click_at(x: int, y: int)
wt. 里的 page_at       page_at(index: int): Page
wt. 里的 code_assert_failed  code_assert_failed: int
console. 里的 print    print(...values)
行首的 page            let page: Page
行首的 case_begin      Run.case_begin(title: string): int
行首的 wt              包 libs/web_test
行首的 console         标准库组
行首的 while           关键字
```

`wt.` 后面那一段里也列得出包里 `export const` 写下的数（`code_assert_failed: int` 那种写法）：它们只能读，不能赋值，也不能加括号调用。

`run.`、`page.`、`wt.` 后面还什么都没有时照样能列出候选：句子写到一半时，扩展在光标处插一个占位名字再走一遍检查，好让点号左边那一段先算出类型；占位名字只为这一次问答存在，不会出现在编辑器里，也不写入文件。

参数名一律是英文小写下划线；只读借用的参数在签名里写成 `ref 名字: 类型`，与声明那一侧一样；元素类型跟着接收者走，写不出真类型时写 `T` / `K` / `V`；变长参数写成 `(...values)`；没有返回值的动作不写冒号那一段。没写 `export` 的函数不会出现在包名后面那一段候选里。

## 悬停

停在方法或函数名上，第一行是签名，下面那几句是写在这个声明上面的注释——中文一段、英文一段、一段标着 `nf` 的示例（下面这一段是从 `webtest/cases/login.nf` 第 25 行实际问出来的答复）：

```text
Run.step(label: string)

脚本里要记录哪一步就调用一次；通过的用例不打印步骤，失败的用例才列出已完成的步骤。

Write one of these for each step you want recorded; a passing case prints nothing, while a failed one lists the steps it got through.

run.step("点开登录")
```

注释在语言里没有语义：词法阶段整段丢掉，编译器看不见它。这一段是扩展按声明所在的行回到原文读出来显示的，写在别的文件里的注释同样读得到。紧贴声明上面那一段才算这条声明的，隔了一个空行就不算；写在注释里的 `en: ` 与 `例：` 两个记号只用来分段，屏幕上不出现。`@param`、`@return` 这类标签语言没有规定意思，屏幕上保持原样。声明上面没写注释，就只给签名那一行。停在包导出的那一个数上也是这三段，第一行换成它的名字与类型（实测：`greet.LIMIT: int`，下面是写在 `export const LIMIT:int = 4096` 上面那中文、英文与示例）。

停在声明那一行的名字上也有答复，第一行是写出来那一份签名。`method twice<Element>(v:Element):Element` 里的 `twice` 答 `twice(v: Element): Element`，类型参数留着自己的名字；同一份文件里 `twice(1)` 那一处答的是这一次调用落到的 `twice(v: int): int`。类体内的方法与接口里的方法声明同样答得出，归属写在名字前面，比如 `Cell.get(): T`、`Shape.perim(): float`。

标准库的那一百四十八个动作没有声明所在的行可以回原文读，它们的中文、英文与示例放在编译器里的一张表上（`compiler/internal/check/docs.go`），屏幕上与库的注释是同一个形状。停在 `number.to_string(rows)` 的动作名上：

```text
number.to_string(value): string

基础类型按各自的格式输出：int、byte、enum 输出十进制，boolean 输出 true／false，unicode 输出对应的字符，float 输出最短往返且必带小数点的写法。……

Formats a basic value by its own rules: int, byte and enum as decimal, boolean as true or false, a code point as that character, a float in its shortest round-trip form and always with a decimal point. …

let tag: string = number.to_string(42)
```

停在类型名上给的是类型本身，再给一句实际的造值写法（`class Box` 与 `new Box(n: int)`，字段名与类型取自声明）。停在标准库的组名上（比如 `console`）给的是组名，后面列出这个组里那些动作的签名。

## 调试

- 断点：点行号左侧。只能停在语句开头那一个位置（一条语句一个检查点），所以表达式中间停不下来。
- 单步：F10 执行下一句，F11 进入函数，Shift+F11 跳出当前函数。
- 变量：每一帧给两个作用域。局部是这一帧上有名字的位置；静态是每份文件顶层的 `let` / `const`，它们不存放在任何一帧里，停在文件顶层时只有这一栏有内容。
- 能查看的值：整数、小数、布尔、字节、码点、文本、`list`、`dict`、`hashset`（一次最多展开 20 项、向内两层）、`class` 与 `struct` 的字段、`null`。没有写过的槽位会如实说明读不出来。
- 停下来时把鼠标停在源码的名字上：答复是当前那个值，后面跟着这个名字写下的地方上面那一段注释（中文、英文、示例三段，与编辑器悬停里看到的是同一段）。变量栏、监视表达式与悬停三处同一套答复。
- 行内的值：把用户设置 `debug.inlineValues` 打开，停在断点时每句里的变量名后面直接跟着它的值。
- 内存视图：沿着变量所在格的地址看一段字节，一次最多 4 KiB，只能查看不能修改。
- 程序写到屏幕上的内容实时回到调试控制台，运行结束后报告退出码。

配置项是 `program`（要调试的那份 `.nf`，默认当前文件）、`args`（交给程序的参数，程序里的 `args` 看得见）与 `breakOnThrow`（默认 `false`；写成 `true` 时，没人接住的那一次抛出会停下来，程序停在抛出那一句上，调用栈与每一帧的变量都读得出来。有人接住的抛出不论开关开不开都不停，那一种现场要自己在 `catch` 那一行下断点。一条抛出只问一次：只写 `try` 与 `finally`、没写 `catch` 的那一种，停在收尾跑完、把那一条接着往外送的那一句上）。没有 `launch.json` 直接按 F5 时使用当前打开的文件。

扩展包里带一份写完的配置示例（`examples/launch.json`，三段：当前文件、带参数的示例、抛出时停下来），连注释一起复制进工程的 `.vscode/launch.json` 就能用。

## 设置

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `nf.path` | 空 | 本机 `nf.exe` 的完整路径。留空时用 `PATH` 里的 `nf`；填了就用这一份，语言服务器与调试器都走它，重载窗口立即生效 |

扩展不带编译器，用哪一份由这一项说：装好扩展之后，把仓库编译出来的 `nf.exe`（Windows x64）路径填进 `nf.path`，或者把它所在的目录加进 `PATH`。两处都没有时，语言服务器起不来，插件窗口会说明去哪里填，并给一个直接跳到这一项的按钮。

这样只有一份编译器说话：本机那一份更新到什么版本，屏幕上就是什么版本。要试自己改过的编译器，重新 `go build` 之后重载窗口就生效，不必重新打包扩展。

## 语言配置

`.nf` 的注释符号（`//` 与 `/* */`）、括号与引号的自动配对、块注释的自动收尾、缩进规则由扩展声明，编辑器自带的注释开关、括号高亮与自动缩进跟着生效。补全、悬停、转到定义、找引用、重命名、格式化文档、参数提示、大纲、折叠与语义着色都由语言服务器答复，扩展这一侧不另算一套规则。

## 已知限制

- 跳到定义只认写出来的名字，不框住名字本身。找引用与重命名只认编译器认得出的名字：标准库的动作、内建类型与组名没有写在源码里的声明，问不到也改不了；写到一半、检查器算不动的文本同样问不到。
- 格式化不动尖括号（`<`、`>`、`<<`、`>>`）前后的空白（类型实参与比较运算共用这几个记号，词法分不清），冒号后面原来有没有空格照旧，块注释内部不重排；词法过不去的文本（字符串没有收尾）不排。
- 重命名在返回改动前先把改完的程序在内存里编译一遍，编译不过就拒绝；程序本来就编译不过时不做这一步校验。
- 补全不处理点号左边是下标或括号的那种中段（`xs[0].`、`(x).`）。
- 大纲、折叠与语义着色认的是编译器认得出的结构：一份写到一半的文本先按 repair 那一步补上没闭合的括号再算，补不出来的那种（字符串没有收尾）这几样暂时没有，语法文件给的那一套着色照旧在。
- 调试不能在表达式中间单步，没有条件断点，表达式也算不了（要看中间结果，先用 `let` 存一个名字），内存只读。抛出时中断要在 `launch.json` 里把 `breakOnThrow` 写成 `true` 才有，且只停在没人接住的那一次。
- 调试只跟着程序自己那一条线程：`thread.start` 起的那一条线程走到断点上不停，栈与变量也读不到它。那一行仍然标成已验证，因为可停的位置确实在。
- 需要 Visual Studio Code 1.90 或更新；扩展不带编译器，本机那一份 `nf.exe` 只能运行在 Windows x64。

## 安装与构建

这一份扩展当前只从本仓库打包安装，没有发布到 Marketplace：

```text
cd compiler
go build -o ../nf.exe ./cmd/nf
cd ../vscode
npm install
npm run check
npm run package
code --install-extension nef-0.7.0.vsix
```

装完还要告诉扩展用哪一份编译器：设置里填 `nf.path`（上面“设置”那一节），或者把 `nf.exe` 所在的目录加进 `PATH`。填了之后重载窗口。

装完重载一次窗口（Ctrl+Shift+P → Reload Window）。`npm run check` 做两件事：把语法文件里那两张名字表与 `nf tokens` 逐个比对，再用 VS Code 使用的 TextMate 引擎把探针与 `samples/` 里的示例程序分词一遍。
